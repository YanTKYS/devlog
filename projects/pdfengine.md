## 1. 最終目標

**既存の日本語PDFの文字をクリックして、Wordのように挿入・削除・長文化など自由に編集し、PDFで保存・再編集する。**

対象は特定の文書種別に限らない。同じ文字数の置換、短文化、長文化、部分編集、保存後の再編集のいずれも、重要な利用場面として扱ってきた（pdfengine `docs/development-rules.md` §1）。

### 用語

| 用語 | この文書での意味 |
| --- | --- |
| glyph（字形） | PDF の中で実際に描かれる1文字分の図形。文字コード・フォント・位置を持つ |
| 局所書換 | PDF の描画命令のうち、編集する文字の部分だけを書き換え、他はそのまま残す方式 |
| タグ | 読み上げや読み順のための論理構造（タグ付きPDF）。MCID は描画と構造を結ぶ番号 |
| redaction | PDF の指定範囲から内容を取り除く機能 |
| 保存成功／実用成功 | 保存成功は「保存したPDFが開け、依頼した変更が反映された」こと。実用成功は、それに加えて検索・コピー、自然な配置、承認外の内容の保護などをすべて満たすこと（同 §2） |
| 固定ケース | 実装の前に、入力PDF・編集内容・合否基準を決めてコミットした評価ケース |

レイアウト変更の許容は、安全性を緩めたという意味ではない。承認は包括承認ではなく、各編集で変更前後・動く範囲・保護する範囲を示す。承認がないときや条件を証明できないときは、安全に拒否する。承認外の内容を壊していないかは、保存前に監査する。

## 3. 実装の主な到達点と、その射程

実PDFで確認できたこと（事実）：

- **局所書換**：選んだ元の文字を実際に除去し、周辺の命令・glyph・資源を保ったまま新しい文字を描く。実在の日本語PDFで、置換・挿入・長文化・短文化・保存後の再編集が成立したケースがある（PR #76・#78・#83・#84 など）。
- **周辺描画・タグの保護**：背景・罫線・下線などの描画を文字と対応付けて扱い、タグ付きPDFでは構造を保ったまま編集する経路を持つ。
- **監査**：保存前に元のPDFと比べ、承認外の文字・描画・画像・注釈・リンク・意味構造・画素が変わっていないかを確かめる。不合格なら出力しない。
- **継続編集**：保存したPDF（とその記録）から開き直し、編集を続けられる。

これらは、**任意のPDFを自由に編集できることを示すものではない**。

- 成功は、固定した実PDFと編集内容の範囲での結果である。独立評価は、PR #83・#84 の 6/14・7/14 について「この固定操作集合の達成率であり、一般のPDF編集成功率として使用しない」と明記している。
- 独立評価の時点（2026-10-20）で、「承認済みテンプレート・帳票・限定ワークフローの精密編集には実用化可能性が高い」「一般的な本文を自由に編集する主経路としては、被覆率と保守費の改善が遅い」と評価されていた。

## 4. 局所書換の拡張の限界と、方式の比較

### 4.1 B2 の拡張で見えたこと

B2 は、段落の枠を記録し、後続の行・装飾・パネル・クリップを編集ごとの承認で動かす方式である。拒否の型ごとに部品を追加して、保存できるケースを広げた。

Issue #120（PR #121）の例（事実）：

- 固定25件の長文化で、拒否の型を実測して分類し、最も多い型の過度な拒否を直した。
- 保存は3件から6件に増えた。**新たな実用成功は0件**だった。増えた3件は、いずれも検索・抽出が不合格（元の文書の字形の隙間など、元の文書でも同じ）。

ParagraphIR の判断文書は、残る拒否と、保存しても実用にならない理由が #118〜#122 を通じて同じ型（後続要素・装飾・入れ物・フォント・元の文書由来の抽出）だったと記録している。

### 4.2 異なる方式を実装して比べた理由

独立評価は、段落中心の編集モデルと領域の再構築を推奨しつつ、それを「設計仮説」とし、比較PoCを次の関門に置いた。B2 に部品を足し続けても、壁が同じ型で繰り返される。このため、局所書換の延長ではない方式を、同じ固定ケース・同じ判定で実装して比べることにした。

| 比較 | 方式 | 固定ケース | 結果（実用成功） | 対照 B2 |
| --- | --- | --- | --- | --- |
| Issue #122 / PR #123 | 経路X：stateless redaction＋段落再描画。毎回、保存済みPDFから段落を読み直し、文字だけを消して書き直す。編集モデルを保持しない | 実PDF 16件（PoC 実装前にコミットで固定） | **0件**（出力前監査の後。保存2件はどちらも代替フォント） | 6件（保存12） |
| Issue #124 / PR #125 | ParagraphIR：段落を1回だけ取り込んで編集モデルにし、以後の編集・Undo はモデル上で行い、変わった行だけを元のPDFへ書き戻す | 実PDF 6件（#122 の16件から選び、PoC 実装前に固定） | **2件**（保存3） | 2件（保存3） |

測定条件と読み方：

- **どちらも選定したケースであり、一般のPDFでの成功率ではない。** #122 の16件は B2 の成功と失敗を混ぜて選んだもので、B2 に有利な偏りがありうると記録されている。
- B2 の値は、コミット済みの評価の転記であり、再実行していない。
- #122：経路Xの最初の実行では、承認外の破壊を含むPDFを2件保存していた（次の行の字形の消失、タグの外への描画）。レビュー後に出力前監査を加え、2件とも書かずに拒否するようにした。表の値は監査後のもの。
- #124：転換の根拠として Issue が事前に定めた条件は、「B2 が拒否または実用不合格だった実PDFで、新しい実用成功を1件以上出す」こと。
  - 結果は**0件**。IR の実用成功2件は、B2 も実用成功していた対照ケース（S-I1・S-W2）である。
  - **S-T1 は IR で初めて保存できた**（B2 は拒否）。ただし実用は不合格。
  - S-T1 の不合格は、編集していない1行目の合字「ﬁ」を Poppler が「fi」と読むためで、元のPDFでも同じ。編集が起こした欠陥ではない。固定した基準（#116：元の文書に由来する差も合格にしない）に従って不合格とした。この基準を変えるかは、利用者の判断事項として残っている。
- 残る拒否（R07・R10・S-L1）の原因は、パネルの容量、後続要素の移動、subset フォントにない字形で、編集モデルの選び方とは別に解く必要があると記録された。

ParagraphIR の判断文書は、IR の利点（モデル上の編集、PDF単体からの再編集と完全な復元、命令の境界からの独立）は実測で確かめたが、それが成功件数を増やさなかったとしている。件数を止めている壁は、編集モデルの外（ページ内の他の要素との関係、フォントの供給、抽出の基準）にある、という整理である。

## 5. 良かった取り組み

- **Issue・PR での追跡**：目的、固定する評価、判断事項を Issue と PR に書き、判断の経緯を後から辿れる。
- **後半の独立レビュー**：実装とは別に、コード・測定記録・公式資料を読む独立のアーキテクチャ評価を行った。比較PoCの関門と、採否の判断基準を事前に書いた。
- **固定評価ケース**：PoC を書く前にケースと判定をコミットし、後から追加・削除しない。同じケースで方式を比べられた。
- **保存前の監査と安全な拒否**：承認外の破壊を含むPDFを出力しない。経路Xの破壊（4.2）や IR の書き戻しの不具合は、監査または評価器が検出し、公開前に止まった。拒否を成功に読み替えない。
- **異なる方式のPoC**：方針の議論だけで決めず、別の方式を小さく実装して同じ判定で測った（経路Xは374行、IR とアダプタは計1,017行。比較対象の B2 は18,430行、`pdfeditor` は20,874行で、扱う範囲は異なる。いずれも判断文書の記録値）。
- **実測に基づく休止判断**：転換の条件を事前に決め、満たさなかったことを根拠に判断した。「実装不能」とはせず、「この規模の投資では、自由な編集の広がりを示せなかった」と結論の範囲を限った。

## 6. 反省と仮説

以下は振り返りの解釈・仮説であり、検証した事実ではない。

- **機能単位の進捗と、最終利用体験への近さを混同しやすかった。**
  - 事実：機能や対応するPDFの型は増え続けたが、#120 のように「保存は増えたが新しい実用成功は0件」という結果が出ている。実用成功の判定が今の形で定義されたのは 2026-11-02 である。
  - 仮説：最終的な利用者操作を基準にした判定を早くから持っていれば、拡張の効果を早く測れた可能性がある。
- **アーキテクチャの再評価や撤退条件を、もっと早く設けられた可能性がある。**
  - 事実：独立評価（10-20）は比較PoCを関門とし、採否の基準表を置いた。実際の転換条件つきの比較（#124）は 11-04 だった。その間は B2 の段階採用のもとで部品の追加が続いた。
  - 仮説：「同じ型の拒否が続いたら方式を比べる」という条件を、採用時に書いておけば、比較を前倒しできたかもしれない。
- **必須の制約と、緩和できる条件の切り分けが遅かった可能性がある。**
  - 事実：当初は元のglyph・フォント・描画・タグの保持を高い水準で求め、レイアウト変更を承認で許す判断は 2026-10-29 に明文化された。
  - 仮説：安全・データ保護（緩めない）と、見た目・レイアウト（承認で変えられる）を初期に分けていれば、試す方式の幅が早く広がった可能性がある。
- **レビュー役も、継続投資の妥当性を定期的に問うべきだった。**
  - 事実：記録上確認できる、方式そのものと継続の妥当性を問う評価は、10-20 の独立評価と 11 月の2回の比較PoCである。通常のPRレビュー（[AI開発体制の記録](../notes/ai-development-workflow.md)の役割分担）では、個々のPRの修正指摘を行っていた。
  - 仮説：「この PR は最終目的に近づけたか」「今の方式を続ける根拠は何か」を節目で問えば、4.1 の傾向に早く気付けた可能性がある。

## 8. 再評価に残すものと、再開のきっかけ

残す資産：

- 固定ケース（#122 の16件、#124 の6件）と、その結果・評価器
- ParagraphIR の PoC（`experiments/paragraph_ir/`）と書き戻しの技法（字形単位の除去、元のタグの中への挿入、状態の正確な復元）
- 保存前の監査
- 独立評価と判断文書（下記の参照）

再評価で確かめること：

- 新しい外部ライブラリ・SDK、組版・フォント供給の技術などで、記録した拒否理由（後続要素・装飾・入れ物の移動、subset フォントにない字形、抽出の基準）を越えられるか。
- 同じ固定ケースと判定で測り、「以前は拒否・実用不合格だったケースで、新しく実用成功したか」を見る。
- 未決の判断事項：元の文書に由来する抽出の差を実用不合格とし続けるか、代替フォントを承認した見た目の変更として認めるか（ParagraphIR 判断文書 §8）。
